# Project abstract

**Deepfake News Detection System**: a web platform that helps a reader check news content and shows what its checks can and cannot say.

Online news increasingly combines written claims with images and video, and any of these parts can be misleading or manipulated. Automatic detectors exist for each part, but published work also shows that detectors lose reliability when the data differs from what they were trained on, and that a confident answer from a model is easily mistaken for proof. This project builds a complete, working platform around that problem and treats honesty about uncertainty as a design requirement.

The system is a React and TypeScript web application with a FastAPI and SQLAlchemy back end, a SQLite or PostgreSQL database, and a machine-learning layer. It provides accounts with roles, a dashboard computed from the database, an analysis history, PDF reports, feedback, an administration area (with an administrator-only model registry). Seven analysis modules are implemented, each labelled with what it is and how it was measured. The **English text module** is a TF-IDF and logistic-regression classifier trained on the GonzaloA/fake_news collection. It reaches 0.973 accuracy on its own held-out test articles, but only 0.552 accuracy and a ROC AUC of 0.549 on LIAR2, a different collection of short political claims. That is close to chance, and below the 0.576 accuracy of answering "fake" every time. Both results are shown side by side, and a result is declined as *Unverified* when the text is too short, is in an unsupported language, or the model is not confident enough. Its explanations are exact, because the model is linear. An **Urdu text model** (experimental) reaches 0.862 accuracy on one small Urdu collection and has no second collection to be tested on. The **image module** applies Error Level Analysis and reads camera metadata. It reports measurements, never a verdict. A **news-address module** fetches a page under strict safety limits, scores the article and compares the website with a short list of known sites, without ever calling an unknown site fake. An **evidence module** retrieves Wikipedia passages (and fact-checks when a key is set), has a pretrained inference model judge whether each supports or contradicts the claim (89% correct on the 71% of claims it decides, on a public set that supplies the evidence), lists every source, and answers *Insufficient Evidence* when nothing reliable is found. An **image-with-text module** compares an image with its headline using CLIP and a fixed written rule. A **video module** samples frames, detects faces, scores each face with a pretrained classifier and aggregates the scores; it is frame-based, needs enough faces for a verdict, and reached a ROC AUC of 0.84 on a dataset it was not calibrated on (95% interval 0.71 to 0.95).

The documentation includes a verified literature review of 40 papers, a research gap analysis, an evaluation protocol, a requirements specification, architecture and data models, an API reference and a 12-month roadmap for a team of four.

The main finding is methodological and recurs across modules: an apparently excellent score on a detector's own data says little about its value on other data. The text model collapsed on a second collection, the first pretrained video classifier scored at chance on Celeb-DF, and the chosen video model is clearly weaker on a second dataset. A platform that reported only the best number would mislead its users, so every module shows what was measured, on what, and what was not. Automated tests cover the back end (263 tests, also run on PostgreSQL), the front end (24 unit tests) and the main user flows in a real browser (48 runs). The recorded runs in `testing_report.md` passed them all.

**Keywords:** fake news detection, deepfake, video frame analysis, image forensics, error level analysis, evidence retrieval, explainable AI, model calibration, cross-dataset evaluation, responsible AI.
